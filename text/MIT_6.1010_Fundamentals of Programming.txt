1.1 The Elements  of Programming
Every powerful language has three mechanisms for accomplishing this:
    - primitive expressions
    - means of combination
    - means of abstraction

In programming, we deal with two kinds of elements:
    - procedures
    - data

Informally, data is stuff that we want to manipulate, and procedure are descriptions of the rules for manipulating the data.

1.1.1 Expressions
You type expression, and the interpreter responds by displaying the result of its evaluating that expression.

One kind of primitive expression you might type is a number.
Expressions representing numbers may be combined with an expression representing a primitive procedure.

    (+ 137 349) => +,-,*,/

Expressions such as these, formed by delimiting a list of expressions within parentheses in order to denote procedure application, are called combinations.
The leftmost element in the list is called the operator, and other elements are called operands.
The convention of placing the operator to the left of the operands is known as prefix notation, and it may be somewhat confusing at first.

    (+ 21 35 12 7)

Combinations can be nested.

1.1.2 Naming and the Environment

We say that the name
identifies a variable whose value is the object.
In the Scheme dialect of Lisp, we name things with define.

    (define size 2)
The interpreter associate the value 2 with the name size.
We can refer to the value 2 by name:
    size

    (* 5 size)

"Define" is our language simplest means of abstraction, for it allows us to see simple names to refer to the results of compound operations.

It should be clear that the possibility of associating values with symbols and later retrieving them means that the interpreter must maintain some sort of memory that keeps track of the name object pairs.
This memory is called the environment (global environment).

1.1.3 Evaluating Combinations
The evaluation rule is recursive in nature.

Symbols such as + and * are also included in the global environment, and are associated with the sequences of machine instructions that are their value.

Notice that the evaluation rule given above does not handle definitions.
For instance, evaluating (define x 3) does not apply define to two arguments.
Such exceptions to the general evaluation rule are called special forms.

1.1.5 The Substitution Model for Procedure Application

Substitution model for procedure application.

    - Applicative order versus normal order
An alternative evaluation model would not evaluate the operands until their values were needed.
Instead it would substitute operand expressions for parameters until it obtained an expression involving only primitive operators, and would then perform the evaluation.

    (sum-of-squares (+ 5 1) (* 5 2))
    (+(square (+ 5 1))(square (* 5 2))      )
    (+(* (+ 5 1) (+ 5 1))(* (* 5 2) (* 5 2)))

This alternative "fully expand and then reduce" evaluation method is known as normal order evaluation, in contrast to the "evaluate the arguments and then apply" method that the interpreter actually uses, which is called applicative order evaluation.

Lisp uses applicative order evaluation, partly because of the additional efficiency obtained from avoiding multiple evaluations of expression.

1.1.6 Conditional Expressions and Predicates
Case analysis, and there is a special form in Lisp for notating such a case analysis.
It is called cond.

    (define (abs x)
        (cond ((> x 0) x)
              ((= x 0) 0)
              ((< x 0) (- x))))


(cond (⟨p1 ⟩ ⟨e1 ⟩)
      (⟨p2 ⟩ ⟨e2 ⟩)
      ...
      (⟨pn ⟩ ⟨en ⟩))


pairs of expressions (<p> <e>) called clauses.

The first expression in each pair is a predicate - that is, an expression whose value is interpreted as either true or false.
The predicate <p1> is evaluated first. If its value is false, then <p2> is evaluated.
If none of the <p> is found to be true, the value of the cond is undefined.

The word predicate is used for procedures that return true or false, as well as for expressions that evaluate to true or false.

(define (abs x)
    (cond ((< x 0) (- x))
          (else       x)))

Here is yet another way to write the absolute-value procedure:
(define (abs x)
    (if (< x 0)

1.1.7 Example: Square Roots by Newton Method

    sqrt(x) = the y such that y >= 0 and y^2 = x

    pseudo-List
    (define (sqrt x)
        (the y (and (>= y 0)
                    (= (square y) x))))

The contrast between function and procedure is a reflection of the general distinction between describing of things and describing how to do things. I.e., between declarative knowledge and imperative knowledge.

In mathematics we are usually concerned with declarative (what is) descriptions, whereas in computer science we are usually concerned with imperative (how to) descriptions.

    Guess       Quotient                 Average
     1           (y/Guess)=2/1=2       (Quotient + Guess)/2 = (2+1)/2=1.5
     1.5         1.3333                  1.4167
     1.4167      1.4118                  1.4142

    (define (good-enough? guess x)
        (< (abs (- (square guess) x)) 0.001))

    (define (average x y)
        (/ (+ x y) 2))

    (define (improve guess x)
        (average guess (/ x guess)))

    (define (sqrt-iter guess x)
        (if (good-enough? guess x)
            guess
            (sqrt-iter (improve guess x)  x)))

    (define (sqrt x)
        (sqrt-iter 1.0 x))

The sqrt program also illustrates that the simple procedural language we have introduced so far is sufficient for writing any purely numerical program that one could write in C or Pascal.
